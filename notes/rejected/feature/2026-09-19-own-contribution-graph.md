# Agent Note: 不换自己的 GitHub 贡献图

## 问题

首屏那张贡献图是复刻对象站长的数据，必须处理。最直觉的方案是「换成自己的」。

## 决策

**否决。** 先用 GitHub GraphQL 把真实贡献数据拉出来再判断，结果：

- 53 周 / 371 天里只有 **6 天**有提交，**1.6%**
- 全年 **20 次**提交，单日最高 **7 次**

一条蛇爬在 98.4% 空白的灰格子上，看起来像页面坏了。
这个方案在**数据层面就被否决了**，不需要等到实现。

改成显示「最近推送的仓库」——同样的信息源，但只取有内容的部分。
（这次替换的完整过程见[首屏贡献图整体移除](2026-09-19-drop-snake-contribution.md)）

## 曾考虑的替代方案

**照抄 `@platane/snk` 的配置跑一遍**——否决（技术上也走不通）。
`@platane/snk` **不在 npm 上**，它是一个 GitHub Action，本地跑不了，
要用必须走 CI 的工作流。改造成本比收益高。

**把时间窗口拉长到两年 / 三年**——否决。填充率会高一点，
但贡献图的语义就是「最近一年的活跃度」，拉长窗口等于改变语义，
而且稀疏的格子仍然难看。

**用别的活动数据替代**（如 commits 总数、star 数）——搁置。
这些数字放在贡献图的视觉框架里会显得空洞 —— 那套视觉是为「密度」设计的，
没有密度就没有信息量。改成数字卡片就是另一个模块了，也就是最终选的方案。

## 后果

- 首页那一块从「图形」变成「列表」，视觉趣味性下降，这是明知的取舍。
- **方法论上留下一条**：涉及「换成自己的数据」时，
  **先把真实数据拉出来看分布，再决定要不要做**。
  这次如果先写代码再拉数据，会白做一整天。
- 数据是构建期生成的（见[第三方 API 改到构建期取数](2026-09-20-github-api-egress-limit.md)），
  顺带把运行时对 GitHub 的依赖也去掉了。
