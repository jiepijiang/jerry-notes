# Agent Note: 不引入 Service Worker

## 问题

复刻对象注册了 `sw.js` 做离线缓存。复刻时要不要跟着抄？

## 决策

**不引入。** 在「已知差异」里列明。

理由是权衡后的：Service Worker 的收益是「离线可访问」和「二次加载更快」，
但这是一个个人主页 ——

- 离线访问的需求几乎不存在（想看的时候都有网）
- Vite 构建已经带内容哈希，静态资源的强缓存由 HTTP 头解决，不需要 SW 插手
- **调试成本很高**：SW 的缓存会让「改了没生效」变成一个高频问题，
  而且它的生命周期（install / activate / skipWaiting / clientsClaim）本身就是一层心智负担

## 曾考虑的替代方案

**跟着抄一个**——否决。为了「1:1 复刻」而引入一个自己都说不清收益的组件，
是纯粹的负债。复刻的目标是视觉与交互，不是技术栈。

**抄一个但默认不注册**——否决。代码留在仓库里就会有人问「这个要不要启用」，
不如干脆不写。

**用 Vite 的 PWA 插件**——否决。同第二个方案，而且多一个依赖。

## 后果

- 少一个需要维护、需要解释的组件。
- 代价：**与复刻对象在「离线可访问」这一项上确实不一致**。
  这属于有意偏离，已经写进 README 的「已知差异」。
- 如果以后真的需要离线（比如知识库要支持断网查看），再引入不迟 ——
  那时会有明确的收益来支撑这个决定，而不是「因为原站有」。
