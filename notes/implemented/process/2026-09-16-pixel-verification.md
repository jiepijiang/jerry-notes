# Agent Note: 复刻类项目的验收流程 —— 先量数字，再比像素

## 问题

复刻一个站点，怎么判断「做完了」？

凭肉眼看截图是不可靠的：字号差 1px、字重差一档、某个元素被 `transform` 偏移了 16px，
这些在整页截图里都看不出来，但在实际浏览时会有说不清的「不对劲」。

## 决策

固定成一套四步流程：

**第一步：拆原站。** 不靠截图猜，先拿源码和资源。压缩过的单行 CSS / JS
**格式化再读** —— 直接读会被截断。
（为什么选「复刻」这条路，见[先用复刻定骨架](2026-09-16-replicate-then-own.md)）

**第二步：量数字。** 在**同一个浏览器会话**里分别加载原站和本地，
对比关键元素的 `getBoundingClientRect()` 与关键计算样式：

```js
const r = el.getBoundingClientRect(), cs = getComputedStyle(el)
// 坐标 / 尺寸允许 1px 误差；字号、字重、颜色必须完全相等
```

**第三步：逐像素验收。** 关键是**先固定状态再截图** ——
主题、语言、开关这类状态变量两边不一致的话，会得到一张「99% 都不对」的假差异图，
然后花大量时间去查根本不存在的问题。**不要用「点开关」的方式切状态**，
要么直接写存储键，要么断言后再截图。截图前还要冻结动画，否则帧差会淹没真实差异。

**第四步：差异要放大看。** 差异带按 6 倍最近邻放大再肉眼确认 ——
常见的「统计上只有几百像素、放大后才发现是颜色错了」的情况：图标、边框、阴影。

## 曾考虑的替代方案

**只看整页像素差异百分比**——否决。百分比会掩盖局部问题：
0.5% 的差异可能来自「站名文字不同」（正常），也可能来自「某个图标颜色错了」（不正常），
统计数字分不出来。

**只做盒模型对比**——否决。盒模型对了不代表渲染对了 ——
`background` 简写会重置 `background-clip` 导致渐变文字失效，
这种问题盒模型完全测不出来。

**人工对比截图**——否决。不可重复、不可回归，而且人对 1~2px 的偏差极不敏感。

## 后果

- 得到 22 项关键元素盒模型「0px 偏差」、整页像素差异 0.57%
  （且全部落在「站名文字不同」和「动画帧不同」的位置）。
- **建立了可回归的基准数字**：页面总高、响应式三档高度、关键元素盒模型。
  之后每次改内容，对一遍就知道有没有顶动布局。
- 代价：**基准数字必须连视口尺寸一起记**。
  垂直居中的容器绝对坐标会随视口高度整体平移 ——
  同一个 600×707 的卡片，视口 900 高时 `y=96.5`、1000 高时 `y=146.5`（差 50px，
  正好是 `(1000-900)/2`）。差点当成回归去查。
  所以**核验内部布局一律用「相对容器顶部的偏移」**，绝对坐标只在同一视口下才可比。
- 另一条：**本地全绿不等于线上对**。部署完要对着真实 URL 把关键路径重跑一次，
  专抓「只在生产走子路径拼接」的资源（字体、音频、数据文件）。
