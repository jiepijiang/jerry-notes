# Agent Note: 别依赖第三方 favicon 服务，用「自带 → 站点根 → 首字母」三级兜底

## 问题

导航站有几百个书签，每个都要显示网站图标。第一版直接用 Google 的
`s2/favicons` 服务按域名批量取 —— 一行代码搞定，本地测试也很完美。

上线后国内访问：**整页图标集体挂掉**。两个原因叠在一起：

1. **不可达**：该服务在国内网络下大量超时。
2. **被限流**：几百个图标并发请求，服务端直接开始拒绝，连能通的那部分也拿不到。

## 决策

改成**三级降级**，而且**第一级永远先显示，不等图片**：

```
数据里指定的 icon  →  站点自己的 /favicon.ico  →  首字母渐变块
```

具体做法：

- **图标位常驻「渐变底 + 首字母」**，图片 `@load` 之后再覆盖上去。
  这样懒加载期间不会出现白板闪烁 —— 首字母先顶着，图来了再换。
- 真实图标一律用**中性浅底 + 4px 内边距**。
  透明底的白色 logo 直接压在渐变上会糊成一团，加个浅底就清楚了。
- 不设超时等待：图片加载失败就保持首字母状态，不重试、不占位。

## 曾考虑的替代方案

**继续用第三方服务，但加并发限制 + 重试**——否决。并发限制能缓解限流，
但解决不了「不可达」。而且引入了一个不受控的可用性依赖。

**构建期把 favicon 抓下来存本地**——搁置。理论上最稳，
但几百个站点的图标要抓、要更新、要处理版权，维护成本远超收益；
而且书签是用户随时增删的，构建期抓不到新加的。

**全部用首字母，不显示真实图标**——否决。视觉上太单调，
而且「一眼认出是哪个站」正是导航站的核心体验。

**用 favicon 代理服务**——否决。同第一个方案，只是换了个依赖对象。

（这套降级策略的上下文见[导航站的数据层与图标策略](2026-09-19-nav-site-bookmarks.md)）

## 后果

- 国内可访问，不依赖任何第三方服务。
- 图标显示从「一次请求」变成「最多两次」（数据里的 icon → 站点 `/favicon.ico`），
  但两次都是直连目标站点，没有中间层。
- 首字母兜底让「取不到图标」这件事看起来是**设计**，而不是**故障**。
- 顺带一条经验：**验收时要等所有图片加载完再截图**。
  用固定 `sleep` 会误判成「图标没出来是 bug」，
  正确做法是 `waitForFunction` 等所有 `img.complete` 为真。
