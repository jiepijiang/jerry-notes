# Agent Note: 拿到字体文件先用要用的字符过一遍，缺字形不会报错只会静默回退

## 问题

复刻时把原站用的 `Pacifico-Regular.ttf` 一起抄了过来。首页大标题一切正常，
直到把站名改成「Jerry」—— **`J` 明显不是 Pacifico 的写法**，
和后面的 `erry` 完全不是一个字体，一眼就看出来拼接的痕迹。

查下来：那份字体只有 **13 KB**，是照着原站用到的字符裁的子集，
缺 `J` 等一大批字形（`ABCDEFGIJKLMNPQRTUVXYZ…` 基本都没有）。
原站标题里恰好没有这些字母，所以一直看不出问题。

**浏览器对缺字形不会报错**，只是静默回退到下一个 font-family ——
这也是它难被发现的原因。

## 决策

从 Google Fonts 取完整版，用 `fontTools.subset` **按可打印 ASCII 重新裁一份**，
42 KB，SIL OFL 1.1 协议，提交进仓库。

并且把「检查字体是否覆盖要用的字符」变成一条固定的验收动作：

```python
from PIL import ImageFont
f = ImageFont.truetype('Pacifico-Regular.ttf', 48)
missing = [c for c in 'Jerry Hello' if f.getbbox(c)[3] == 0]   # 高度 0 = 缺字形
```

## 曾考虑的替代方案

**直接用完整版字体（不裁）**——否决。完整版 Pacifico 有几百 KB，
一个装饰性标题不值得这个体积；而裁到 ASCII 已经覆盖了标题可能出现的全部字符。

**换一个字体**——否决。Pacifico 的圆润手写感和这个站的整体调性是一套的，
换字体要连带调整字号和字距。

**让标题避开缺失字符**——否决。这是把问题藏起来，而且我改不了自己的名字。

## 后果

- 标题字体一致，`J` 不再掉字形。
- 体积 13 KB → 42 KB，对一个装饰性字体完全可以接受。
- **一条更值钱的副产物**：校验字体时不要用 `document.fonts.check('64px Pacifico')`。
  它**对非 webfont 家族一律返回 true** ——
  因为「Pacifico」和「一个真不存在的字体」都会回退到同一个默认字体，
  量出来的宽度当然相等，于是误判成「字体没问题」。
  正确做法是**按 CSS 里声明的 `font-family` 名去查**（这里声明的是 `title`，不是文件名），
  并和一个真不存在的 family 对比宽度，**不相等才是真字形**。
  这类「校验方法本身有假阳性」的坑，在[复刻类项目的验收流程](2026-09-16-pixel-verification.md)
  里还有几个。
