# Agent Note: 主题逻辑用真值表定优先级，别读源码猜

## 问题

复刻对象的主题切换有三处代码在写同一个状态：

- 首页 `script.js` 写 `cookie('themeState')`
- 留言板内联脚本写另一套
- 两个页面都加载的 `loader.bundle.js` 写第三套

三套的规则不一样，读源码推断「谁最后生效」很容易得出错误结论 ——
因为脚本按文档顺序执行、又都注册在 `DOMContentLoaded` 上，
「谁最后注册谁赢」这个规律在跨文件、跨异步加载时并不成立。

## 决策

不读源码，**直接跑组合矩阵**。把三个状态源（cookie / localStorage / 系统偏好）的
所有组合穷举出来，每种组合都「预置状态 → 进页面 → 读最终 `data-theme`」，输出成表。

8 种组合跑完，结论很干净：

```
data-theme = localStorage('theme') || (系统深色 ? 'Dark' : 'Light')
```

最终由 `loader.bundle.js` 胜出。而首页那个 `cookie('themeState')` 是**死代码** ——
只写不读，而且负责改写它的 `#myonoffswitch` 元素在 DOM 里根本不存在。

## 曾考虑的替代方案

**按源码顺序推断优先级**——否决。三套逻辑分布在三个文件、还有异步加载，
执行顺序不能靠阅读确定。推断错了要等用户反馈才发现，成本高得多。

**只实现最后那套，不管前两套**——否决。虽然结论一样，但没有真值表就没有证据；
万一以后改了加载方式（比如把 `loader.bundle.js` 改成 defer），优先级会变。

**三套都实现，让浏览器自己决定**——否决。这是把不确定性留进代码，
而且前两套本来就是死代码，实现它等于给自己埋雷。

## 后果

- 得到一条可验证的规则，写进 `useTheme.js` 顶部注释，以后谁改都能对上。
- **不再写那个 `themeState` cookie** —— 死代码不复制。
  （详见[不复制原站的死代码](2026-09-19-drop-dead-theme-code.md)）
- 顺带发现原站一个真 bug：系统深色 + 从未手动切换过时，页面已经是 Dark，
  但开关滑块停在左侧（`checked` 只按 `localStorage` 算），要点两下才切到 Light。
  这里选择修掉（滑块反映真实主题），并在「已知差异」里列明。
- 代价：多花了半天做穷举。但这半天换来的是「不用再回来查」。
