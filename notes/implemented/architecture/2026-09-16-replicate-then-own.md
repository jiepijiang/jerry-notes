# Agent Note: 先用复刻定骨架，再逐块换成自己的内容

## 问题

想做一个个人主页，但「从零设计」这件事本身很贵：版式、动效、响应式断点、加载动画、
主题变量……每一项单独看都不难，合在一起就是几天的反复调。而我对「最终长什么样」还没有明确答案，
先设计再实现，很可能返工。

## 决策

选一个视觉上已经成立的站点（`xywml.com`），**把它的 UI / 动效 / 布局一比一复刻下来**，
作为骨架；内容与视图彻底分离（全部文案集中在 `src/data/site.js`），之后逐块替换成自己的。

复刻过程中坚持三条：

1. **量数字，不靠眼睛。** 用 Playwright 同会话加载原站与本地，对比 `getBoundingClientRect()`
   与计算样式，坐标允许 1px 误差、字号字重颜色必须完全相等。眼睛看不出的偏差全在这一步暴露。
   （完整流程见[复刻类项目的验收流程](2026-09-16-pixel-verification.md)）
2. **如实保留原站「写了但没生效」的规则。** 复刻的目标是还原渲染结果，不是修 bug。
   想修就补注释、做成开关，别默默改掉。
3. **留一份「已知差异」清单。** 每条写明原因和怎么还原，否则半年后自己也看不懂哪里动过。

## 曾考虑的替代方案

**直接用现成主题**（Hexo / Hugo 主题）——否决。主题给的是「一篇篇博客文章」的版式，
而我要的是一个门户式单页，改造主题的工作量不比复刻小，还会被主题的结构绑住。

**从零手写**——否决。视觉方向没定之前，手写等于把「设计」和「实现」两件事捆在一起做，
每次调整设计都要动代码。

**照抄原站源码**——否决。原站是多个独立 HTML 文档 + 全局 CSS + 一堆 jQuery 时代的脚本，
类名互相污染（`.logo` / `.card` 在两个页面里指不同东西）。照抄只能得到一个静态页面，
没法做成 SPA，也没法维护。

## 后果

- 好处：**开工第一天就有一个能看的完整页面**，之后所有精力都花在内容和局部增强上，
  不用再纠结「这个间距是不是好看」。
- 代价：背上了一份「复刻保真度」的维护责任。改了内容就可能顶动布局，
  所以留了一套基准数字（页面总高、关键元素盒模型）当回归指标，
  每次改完都要对一遍。
- 后续：站点从 `jerry-blog` 改名 `jerry-site`，定位从「博客」改成「个人门户」，
  博客正文拆到独立仓库 —— 骨架能撑住这个变化，说明当初选对了。
  （拆法见[主站与子站拆成独立仓库](2026-09-19-multi-repo-split.md)）
