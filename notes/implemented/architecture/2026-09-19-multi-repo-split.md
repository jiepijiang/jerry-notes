# Agent Note: 主站与子站拆成独立仓库，各自独立部署

## 问题

个人站点会不断长出新的部分：导航站、知识库、以后可能还有博客正文、图床、小工具集。
如果全塞进一个仓库：

- 一次构建要重新打包所有部分，改一个错别字也要等全量构建
- 主站的 bundle 会持续膨胀，首屏变慢
- 各部分的依赖会互相打架（比如导航站想上 Supabase，主站不需要）
- 部署耦合：子站挂掉会把主站一起带下去

## 决策

**一个主站 + 若干子站，每个子站一个独立仓库、一套独立的 GitHub Pages 部署。**
主站只做一件事：在 `site` 区挂入口卡片指过去。

各仓库共用同一套技术栈与约定（Vue 3 + Vite + vue-router，无 UI 框架），
把「子路径适配」这件事固定成一份可以照抄的模板：

```js
// vite.config.js —— 换仓库名只改这一行
const REPO_NAME = 'jerry-notes'
base: command === 'build' ? `/${REPO_NAME}/` : '/'
```

外加一个 `spaFallbackPlugin`：构建完把 `index.html` 复制成 `404.html`，
让 Pages 的 SPA 深链能回退。代价是深链的 HTTP 状态码仍是 404（页面正常渲染），
这个取舍是明知的，写进 README 免得以后被当成 bug 查。

## 曾考虑的替代方案

**Monorepo（pnpm workspace + 一个 Pages 站点）**——否决。收益是共享组件，
但代价是每次部署都要全量构建，而且我已经有一套成熟的主站样式，
共享的其实是「约定」而不是「代码」，用文档固定约定就够了。

**主站加一个 `/notes` 路由**——否决。知识库的笔记数据会持续增长，
放进主站 bundle 等于给首屏加负担，而知识库本身并不需要那么快的首屏。

**用子域名区分**（`notes.jerry.dev`）——暂时搁置。需要自定义域名和 DNS 配置，
而现在连主域名都还没绑。Pages 的子路径已经够用，以后想换只改 `base` 一行。

## 后果

- 每个子站可以独立演进：导航站上 Supabase 不影响主站，知识库换数据结构不影响导航站。
  已落地的两个子站：[网址导航与书签管理](2026-09-19-nav-site-bookmarks.md)、本知识库。
- 主站的 site 区变成一张「目录」，加新东西只要加一张卡片。
- 代价：**样式没法直接复用**。主站的设计语言（深色毛玻璃、`--item_bg_color`、
  全局遮罩层）要靠手工抄一份到子站。抄错了视觉就会飘 ——
  所以每个子站都要跑一次「对着主站截图比对」。
- 已知会踩的坑：子路径部署时，**JS 字符串里的 `/static/...` 不会被 Vite 重写**
  （它只处理 `index.html` 和 CSS 的 `url()`），必须自己包一层 `asset()` 拼 `BASE_URL`。
