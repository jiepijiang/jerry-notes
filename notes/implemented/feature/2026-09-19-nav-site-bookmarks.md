# Agent Note: 导航站的数据层与图标策略

## 问题

想要一个自己的网址导航页。参考实现（`dh.huhage.fun`）功能完整：书签管理、
分类、发现页、图标自动抓取。

两个关键决策点：

1. **数据存哪**（涉及以后换后端）
2. **图标怎么来**（涉及几百个外部站点的可用性）

## 决策

**数据层做成可替换适配器**（详见[导航站先不上 Supabase](2026-09-20-supabase-now.md)），
业务键统一 `jt:` 前缀。

**图标做三级降级**（详见[别依赖第三方 favicon 服务](2026-09-19-google-favicon-service.md)）：

```
数据里指定的 icon → 站点自己的 /favicon.ico → 首字母渐变块
```

图标位**常驻「渐变底 + 首字母」**，图片 `@load` 之后再覆盖上去，
避免懒加载期间的白板闪烁。

**视觉沿用主站的设计语言**，但补了一套浅色主题。
主站本身只有深色一套（复刻对象就是深色毛玻璃），而导航站是每天要用的工具页，
白天用深色不合适。

补浅色时踩了一个坑：主站的背景处理是「背景图 + 一层全局遮罩」，
只铺 `background-image` 不加遮罩层，深色下背景会又亮又锐、正文压不住：

```css
body::before {
  position: fixed; inset: 0; z-index: -99999999;
  background: rgba(0, 0, 0, .19);
  backdrop-filter: blur(19px);
}
```

浅色是新补的，需要相反的处理：**白色薄纱 + 降饱和**，
否则日落照片的暖色块会透出来发浑。

## 曾考虑的替代方案

**不做分类，全部平铺**——否决。几百个书签平铺等于没有导航。

**用浏览器自带的书签栏**——否决。跨设备不同步，而且没法分享和整理。

**图标全部手填**——否决。几百个站点手工找图标不现实，
而且书签是随时增删的。

**主站浅色主题一起做**——否决。主站是复刻项目，动它的主题会破坏保真度；
导航站是新项目，可以自由设计。

## 后果

- 国内可访问、离线可用、零后端。
- 代价：**浅色主题需要单独维护一套颜色变量**。
  主站的变量是为深色调的，浅色下对比度、边框、阴影都要重设一遍，
  不能直接复用。
- 发现页种子数据做了链接存活检测，从 385 条里剔掉 6 条死链，留 377 条。
  **这类数据要定期重跑检测**，否则会慢慢烂掉。
