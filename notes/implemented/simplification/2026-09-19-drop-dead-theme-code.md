# Agent Note: 不复制原站的死代码，主题只留一套生效逻辑

## 问题

复刻过程中发现原站有两处「写了但从来没生效」的主题相关代码：

1. **只写不读的 cookie**：首页 `script.js` 往 `themeState` 写主题，
   但没有任何地方读它；而负责改写它的 `#myonoffswitch` 元素在 DOM 里根本不存在。
   这是彻底的死代码。
2. **四套从未生效的主题变量**：`root.css` 把 5 套主题塞进同一个 `html{}` 规则里，
   CSS 的「后者覆盖前者」让最终生效的永远是第 5 套（深色毛玻璃）。
   `data-theme` 实际只影响贪吃蛇配色和加载动画场景。

## 决策

**复刻的是渲染结果，不是源码。** 两处死代码都不复制：

- 不再写 `themeState` cookie，主题只存 `localStorage` 一份。
  （原站首页写 cookie、留言板写 localStorage，两边互不相通，
  在首页切换主题跳到留言板会「变回去」—— 这个 bug 也一并消失。）
- `root.css` 只落地生效的那一套变量，其余 4 套**以注释形式保留**，
  改 `data-theme` 选择器就能启用。

在代码注释里写明「为什么这里只有一套」，并在 README 的「已知差异」中列明。
（优先级是怎么定下来的，见[主题逻辑用真值表定优先级](2026-09-16-theme-truth-table.md)）

## 曾考虑的替代方案

**如实照抄 5 套变量（保持 1:1）**——否决。5 套变量会让后来的人以为
「改 `data-theme` 就能换主题」，而实际上不能，这是个主动埋的雷。
注释形式既保留了信息，又不会误导。

**照抄那个 cookie 的写法**——否决。纯粹是负担，而且会重新引入
「两个页面主题不同步」的问题。

**顺手把 5 套主题都做成真的可切换**——否决。那是给复刻对象加新功能，
不是复刻。而且 5 套主题里另外 4 套的视觉都没调过，切过去只会更难看。

## 后果

- 主题相关的代码量减少一半以上，且只有一条规则：
  `data-theme = localStorage('theme') || (系统深色 ? 'Dark' : 'Light')`。
- 顺手修掉原站「滑块位置和实际主题不符」的 bug（系统深色 + 从未切换过时，
  页面已经是 Dark 但滑块停在左侧，要点两下才切到 Light）。
- **代价：多了一份需要维护的「已知差异」清单。**
  每一条都要写清「原站是什么样、我改成了什么、想还原怎么改」——
  这是复刻类项目的固有成本，躲不掉，只能写清楚。
